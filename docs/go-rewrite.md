# Maildrop Go 重写说明

本文记录从 Python（Flask + aiosmtpd）迁移到 Go 时的设计约定、兼容性保证与有意的行为变化，
供后续维护参考。模块结构与开发命令见仓库根目录的 `AGENTS.md`。

## 1. 兼容性约定

- **API**：`/api/*` 与 `/api/admin/*` 的路径、方法、鉴权方式、JSON 字段名与类型、状态码和错误文案
  均与 Python 版一致，现有前端无需改动。新增的只有域名接口与少量追加字段（见第 3 节）。
- **配置**：环境变量名称与默认值不变，`.env` 可直接沿用。`USE_DATABASE=false`（JSON 存储）
  与 `FLASK_SECRET_KEY` 已不再使用，启动时会给出警告并忽略。
- **数据库**：启动时自动迁移 Python 历史版本创建的 `mailbox.db`。迁移结果与 Python 版
  `init_tables` 的表结构逐列一致，基准保存在 `internal/store/testdata/python_schema_*.json`
  （移除 Python 前由其真实迁移生成，不要手工修改）。Go 版新增内容只追加，不改原有列：
  - `domains` 表（域名设置）；
  - `mailboxes.admin_disabled` 列（管理员禁用标记），位于表末尾。
  Python 旧代码按显式列名读写，回滚后可以忽略这些新增内容。
- **旧数据容错**：Python 可能写入小数保留天数、非法 JSON 列表等数据。迁移会把整数列中的
  REAL 值截断为整数，读取时也容忍这类值，不会因为单条旧数据导致邮箱无法鉴权或收信。

## 2. 关键设计

- **单进程**：`cmd/maildrop` 同时运行 HTTP、SMTP 与定时清理；收到 SIGINT/SIGTERM 后并行关闭，
  超时强制断开，等在途请求结束后再关闭数据库。
- **SQLite 单连接**：`internal/store` 使用 WAL + 单连接池串行化写入，事务以 `BEGIN IMMEDIATE`
  开启。**在 `store.WithTx` 回调中只能使用传入的 `*sql.Tx`，不得调用 `Store` 方法或 `Store.DB()`，
  否则会死锁。**
- **按信封投递**：SMTP 以 `RCPT TO` 决定投递目标，邮件头的 `To` 只作展示；每个收件人独立判定，
  整批在同一事务中写入。至少一个收件人成功返回 `250`，全部被拒返回 `550` 与原因，
  内部错误返回可重试的 `451`。原始邮件大小上限为 `2 × MAX_EMAIL_SIZE + 1 MiB`。
- **容量记账**：容量检查、写入、`storage_used` 增减与超量裁剪在同一事务内完成；所有删除路径
  （删信、批删、删邮箱、数量裁剪、定时清理）都同步扣减已用容量。
- **客户端 IP**：全站只通过 `ipguard.ClientIP` 获取。`TRUST_PROXY_HOPS=N` 时取
  `X-Forwarded-For` 从右数第 N 项，按逗号切分且必须是合法 IP，否则回退到连接地址。
- **前端内嵌**：`embed.go` 打包 `src/frontend/templates/*.html` 与 `static/` 下的四个子目录。
  模板是纯 HTML，静态资源以 `/static/...` 绝对路径引用，响应带强 ETag，
  并设置 `Cache-Control: no-cache`。新增静态目录需同步修改 `embed.go`。
- **页面安全头**：`/web/*`（含 404）带完整的私密页面头与严格 CSP；`/admin` 仍使用内联事件处理，
  因此不加严格 CSP。

## 3. 有意的行为变化

| 范围 | Python 版 | Go 版 |
| --- | --- | --- |
| 域名配置 | 只读 `.env` 的 `DOMAINS` | 存数据库，在后台「域名设置」管理，修改立即生效；`DOMAINS` 仅在域名表为空时导入。禁用域名只影响新建邮箱 |
| 子管理员域名 | 只看授权域名 | 授权域名中排除在「域名设置」里被禁用的域名；不在域名表中的授权域名仍可用 |
| 收件路由 | 按邮件头 `To` | 按 SMTP 信封收件人，密送与转发可正确送达；收件域名不区分大小写 |
| 发件人白名单 | 区分大小写；只有 `@domain` 才是域名规则 | 不区分大小写；不含 `@` 的条目也按域名处理。仍只检查邮件头 From |
| 允许的域名（邮箱级） | 保存了但从未生效 | 按邮件头 From 的域名（含子域名）限制收信，与白名单同时满足才收 |
| 附件 | 文本附件会覆盖正文 | 带 `Content-Disposition: attachment` 的文本部分不再覆盖正文 |
| 定时清理 | 数据库模式下实际清理的是 JSON 文件 | 定期清理过期邮箱与邮件，遵循 `EMAIL_RETENTION_SECONDS`，同时清理过期的 IP 封禁记录 |
| 管理员禁用 | 邮箱持有者可通过公开接口自行恢复 | 管理员禁用（软删除、批量软删除、设为停用）会写入 `admin_disabled`，公开接口返回 `423` 拒绝恢复；管理员启用时清除该标记 |
| 保护地址 | 只在管理员创建时检查 | `PROTECTED_ADDRESSES` 对所有创建入口生效（含子管理员与密码注册）；空规则表示不保护（Python 会误判为全部受保护） |
| 密钥换令牌 | 不计失败次数 | 检查 IP 封禁并累计失败次数，状态码不变（类型错误 400、不存在 404、密钥错误 401） |
| IP 白名单 | 数据库模式隐式放行 localhost/unknown；一条坏规则会让后续规则失效 | 只放行明确列出的地址，坏规则逐条跳过并记录日志 |
| 管理分页与审计查询 | `page_size=0` 除零报错；`limit` 为负数时不限条数 | 分页限制在 1–200，审计日志限制在 1–1000 条 |
| 数据写入校验 | 白名单、允许域名可写入非字符串或非列表 | 写入时严格校验为字符串数组，允许域名需是合法域名并会规范化 |

## 4. 保留的已知问题

- 每次启动都会把 50MB 或未设置的邮箱容量上限重置为 3MB（Python 原有迁移逻辑）。
  为了兼容暂时保留，是否取消需要单独决定。
- 管理员密码通过 `Authorization: Bearer <密码>` 发送，并保存在前端的 `sessionStorage`（原有设计）。
  更稳妥的做法是登录后签发有时效的会话令牌，涉及前后端协议变更。
- 域名变更与对应的审计记录分两次提交；审计写入失败时，域名变更已经生效。
- `PROTECTED_ADDRESSES` 使用 Go 的 RE2 语法，不支持 Python 正则的回溯、前瞻等特性；
  无法解析的规则会拒绝所有创建请求，不会被悄悄绕过。

## 5. 测试

- `go vet ./... && go test ./...`：各包单元测试与 HTTP、SMTP 集成测试。
- `python -m pytest -q tests`：前端文件契约测试。
- `python scripts/verify_ui_browser.py --quick --skip-perf`：自动编译并启动 Go 服务，
  在真实浏览器中回归页面与交互；去掉 `--quick --skip-perf` 跑多浏览器、多尺寸与性能检查。
